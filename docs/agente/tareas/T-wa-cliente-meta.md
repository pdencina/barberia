# T-wa-cliente-meta (codigo, espera a Claude)
Archivos: `src/lib/agente/whatsapp-meta.ts` y `scripts/test-agente-whatsapp-meta.ts`. Cliente MINIMO de la API de WhatsApp Cloud de Meta, PURO: recibe `fetch`, token, version y `phone_number_id` como PARAMETROS (nunca lee process.env ni la red por su cuenta; nunca imprime ni guarda el token).
Funciones: (a) `enviarPlantilla({ para, plantilla, idioma, variables })` -> resultado `{estado:'aceptado', id}` | `{estado:'fallido'}` | `{estado:'incierto'}` con la misma logica que `enviarInformeConResultado` (error claro de rechazo antes de enviar = fallido; timeout, 5xx, respuesta perdida = incierto; no reenviar a ciegas); (b) `resolverDesafioWebhook(query, tokenEsperado)` para la verificacion GET de Meta (hub.mode, hub.verify_token, hub.challenge) en tiempo constante; (c) `extraerMensajesEntrantes(payload)` que devuelve solo lo minimo necesario (id del mensaje del proveedor, tipo, `phone_number_id` del negocio, hash del remitente y el texto SOLO en memoria para clasificar, nunca en el resultado persistible) y descarta todo lo demas. Verifica el formato real en la documentacion oficial de Meta (URL y fecha); si no abre, DESCONOCIDO y deja el contrato generico.
Pruebas con 60+ casos simulados: plantilla ok, rechazo, 5xx, timeout, respuesta sin id, desafio valido/invalido/vacio, payload con estados de entrega (no son mensajes), payload con varios mensajes, tipos no texto (imagen, audio, sticker: se reportan como tipo, sin contenido), payload malformado, texto enorme, ningun log ni salida con telefonos o tokens.
